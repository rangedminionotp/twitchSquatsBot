# Squat Capture 使用说明

[English README](README.md)

给 Twitch 主播用的本地深蹲工具：观众兑换排队，你方便时手动开始；订阅和打赏可以增加欠下的次数。普通摄像头和动作识别共用同一个浏览器视频流。

**目前是内测版，需要从源码启动，不是双击安装的软件。** 先私下测试摄像头、识别和直播来源，再正式使用。

## 1. 安装与启动

下载仓库 ZIP 并解压，或用 Git 克隆仓库。安装 Python 3，在项目目录打开终端。需要联网安装依赖、登录 Twitch 和加载动作模型。

### Windows PowerShell

```powershell
.\scripts\start_windows.ps1
```

如果脚本被执行策略阻止，可不修改策略，改为依次运行：

```powershell
py -m venv .venv
.\.venv\Scripts\python.exe -m squat_capture.startup_check --repair
.\.venv\Scripts\python.exe -m squat_capture
```

自检通过后才执行最后一条。没有 `py` 时，第一条使用已安装的 `python`。

### WSL / Bash

在 WSL 项目目录运行：

```bash
sudo apt update
sudo apt install python3 python3-venv
bash scripts/start_wsl.sh
```

已安装 Python 和 venv 后，日常只需最后一条。不要在 Bash 里执行 PowerShell 脚本。

启动脚本会检查已有虚拟环境、依赖和数据目录，必要时尝试补装；端口占用会提示，不会自动关闭别的程序。**终端要一直保持运行。** Windows 和 WSL 默认使用不同的数据目录，不要随意切换运行方式。

## 2. 三个页面分别做什么

| 页面 | 地址 | 使用方式 |
|---|---|---|
| 控制面板 | http://127.0.0.1:8080/control | 登录、规则、队列、切模式、查看状态 |
| 摄像头画面 | http://127.0.0.1:8080/camera-overlay | Chrome / Edge 独立窗口，再由 Streamlabs **窗口捕获** |
| 数字卡片 | http://127.0.0.1:8080/overlay | OBS / Streamlabs 的 **Browser Source（浏览器源）** |

摄像头页面不是数字卡片，不要把二者的添加方式搞反。不需要 virtual camera，也不需要 public URL 或 ngrok。

## 3. 首次设置

1. 打开控制面板的 **Quick setup**。
2. 点 **Connect with Twitch**，授权你自己的主播账号。普通用户不用填写 Client ID / Client Secret。
3. 在 **Reward** 里选择要监听的频道积分奖励，点 **Save reward**。
4. 奖励名称建议写成 `10 squats`：程序读取标题里的**第一个数字**作为次数；没有数字时默认 10。不要把无关数字放在前面。
5. 按需启用 **Auto-add squats**，设置 Sub、Bits、Streamlabs、StreamElements 的加数规则并保存。
6. 首次启用 Sub / Bits 后重新连接 Twitch，授予所需权限。查看 **Connection health**，确认对应监听已就绪，不能只看登录成功。
7. 已经欠观众的次数，可在 **Your progress → Adjust totals → Set owed** 设置。这里是替换总值，不是在原值上增加。

摄像头和 OBS 的向导勾选框是你手动确认，不代表程序自动验证过。

## 4. 让 Streamlabs 显示摄像头

1. 停用原来的摄像头源，关闭其他占用摄像头的软件及旧 `/squat-popup` 页面。只隐藏来源不一定会释放设备。
2. 用 Windows 的 **Chrome / Edge 独立窗口**打开 Camera Overlay，不是聊天软件内置浏览器。
3. 点 **Start Camera**，允许权限，选择设备。先确认浏览器能看到你。
4. Streamlabs / OBS 添加 **Window Capture（窗口捕获）**，选择 `Squat Capture · Camera Overlay` 所在浏览器窗口。
5. 必要时裁掉地址栏；私人网页放在别的窗口，避免误播。
6. 摄像头页按 **H** 隐藏／显示设置。窗口保持打开，不要最小化。

控制面板里的按钮：

- **Webcam**：普通画面，不识别、不计数；同时暂停正在运行的队列。
- **Capture squats**：自由练习，计入实际完成次数，但不启动暂停中的队列。
- **Start / resume queue**：切到 Capture，开始按顺序处理兑换挑战。

只开一个 Camera Overlay。关闭占用页面后，另一个页面可能需要等待约 8 秒，再点 Start Camera。控制面板会显示摄像头、模型、人体检测、请求模式、实际模式和保存状态；它不能检测 Streamlabs 是否正确出画面。

本地摄像头页先点 **Calibrate**：自然站稳约 1.5 秒 → 示范一次舒适的深蹲、在底部稍停 → 回到站姿。
**校准示范不改计数**。程序学习你的站姿、画面中的膝角和髋部高度变化，不再统一要求 155°／120°。
侧身只需一边肩膀和一整条腿可靠可见；短暂丢点会容错，长时间识别中断则需要先站直再开始。

暂停保留当前窗口的校准；刷新、重开或换摄像头需要重做。移动摄像头／站位后请点 **Recalibrate**，
检测到明显的脚部位置或画面尺寸变化也会要求重新校准。它是次数估计，不是动作规范或安全鉴定；
识别不到时调整站位，不要为了计数强行蹲得更深。校准后先核对几次：**正式动作会改变欠账**。
独立的云端预览目前仍使用旧版检测器。

数字卡片另加 Browser Source，地址用 `/overlay`，尺寸可以从 **460 × 440** 开始。队列详情目前以控制面板为准，不要假设卡片里旧的挑战进度区会展示全部队列状态。

## 5. 欠账、完成次数和队列

| 情况 | Owed 总欠账 | Completed 本场完成 | 队列 |
|---|---|---|---|
| 兑换 N 个深蹲 | 不变 | 不变 | 新增 N 次挑战，同一兑换去重 |
| 新订阅／赠订／Bits／打赏 | 按规则增加 | 不变 | 不插队 |
| 运行队列时完成 1 个 | −1，最低为 0 | 已确认直播中时 +1 | 推进 1 个 |
| 自由 Capture 完成 1 个 | −1，最低为 0 | 已确认直播中时 +1 | 不推进暂停队列 |
| 检测到下一场 Twitch 直播 | 保留 | 清零 | 保留 |

**Owed 是未来要完成的总欠账**，由已开启的订阅／Bits／打赏规则或手动调整增加。
Channel Points 兑换只增加当前挑战，不增加总欠账；完成挑战的动作也能抵扣欠账，每次只扣一次。
即使 Owed 已归零，当前挑战剩余的次数仍要完成。挑战和自由 Capture 的动作都计入完成数。

升级时保留已有总数，不自动反算旧版本兑换加过的欠账；如需纠正历史总量，使用 **Adjust totals**。

- 兑换只排队，不突然打开摄像头、不自动切模式、不锁游戏。
- **Pause · Webcam** 暂停并保留进度；重启服务后队列仍在，默认暂停。
- 队列做完后仍留在 Capture，可继续自由练习；想停止计数要选 Webcam。
- 每约 15 秒检查一次 Twitch 直播状态。同一直播里重启软件不清零；下播后保留最后一场的成绩。
- 离线／直播状态未知时，实际动作仍扣欠账、增加内部历史总数，但不加本场 Completed。
- 延迟补传按服务收到时的直播状态归属，不会回填历史场次。
- 没有自动退款／标记 Twitch 奖励完成，也尚无队列取消、排序或撤销按钮。需要时在 Twitch 端另行处理。

## 6. 自动加数与测试

每个来源可独立开关、设置比例：

- **Sub**：新订阅和赠订；赠送 5 份按 5 份算。**暂不计算自动续订／续订聊天通知。**
- **Bits**：例如每 100 Bits 加 3 次，250 Bits 加 6 次。
  可开启 **Large Cheer bundle** 大额档位：先算完整的大额档，再按基础比例算剩余 Bits。
  比如基础 100→1、大额 1000→15，则 500→5、1200→17、2000→30。
  两笔 500 仍各加 5，不合并凑档；不足基础单位的余数不累计。大额单位必须是基础单位的更大整数倍。
- **Streamlabs / StreamElements**：分别设置金额、币种、增加次数；例如每 USD 2.50 加 4 次，USD 5.01 加 8 次。

只想让订阅增加 Total owed：在 **Integrations → Auto-add squats** 仅开启 Twitch subs，
关闭 Bits、Streamlabs 和 StreamElements，保存规则。每个 Sub 的次数保持自定义；赠订按份数算。
Channel Points 只进入 Next set／挑战队列，不增加 Total owed；完成挑战仍可抵扣已有欠账。

按每笔完整单位换算，余数不累计；其他币种忽略，不做汇率换算。第三方打赏需填写平台凭据，参见 [英文说明](README.md#5-sub-bits-and-donation-rules)。同一笔打赏不要通过两个平台重复转发。

**Safe rule test** 只预览已保存规则，不扣款、不改计数，也不能证明真实事件已经送达。平台自己的测试打赏提醒可能被当成真实事件，不等同于安全测试。

应用没运行时漏掉的事件不会自动补齐，打赏退款也不会自动反向扣除。最近 100 条计数记录会保存；最近 30 条支持事件处理提示在重启后清空，不是完整历史账本。

## 7. 每次直播的简短流程

**开播前**：启动服务 → 检查监听 → 打开摄像头 → 检查窗口捕获和数字卡片 → 隐藏摄像头设置 → 保持 Webcam。

**方便运动时**：点 Start / resume queue；需要休息时点 Pause · Webcam。

**结束时**：切回 Webcam → 摄像头页按 H 检查 **All reps synced** → 关闭摄像头页 → 终端 Ctrl+C。Ctrl+C 后的 KeyboardInterrupt 通常是正常退出提示。

## 8. 保存、备份与安全

- 原生 Windows：`%USERPROFILE%\.squat-capture`
- WSL：Linux 用户目录下的 `~/.squat-capture`
- 自定义：环境变量 `SQUAT_CAPTURE_DATA_DIR`

`config.json` 含账号凭据，不能公开；`stats.json` 含计数、队列、去重记录和最近活动。等同步完成并停止服务后，可手动复制这两个文件到私人位置备份。恢复也要先停服务。恢复旧文件会连同旧的去重记录一起恢复，不能当作普通撤销功能。

未提交计数先保存在浏览器本地，刷新后可补传。必须用**同一个浏览器配置、同一个网址和端口**。`localhost` 和 `127.0.0.1` 是不同来源；清除网站数据、切换浏览器或结束隐私浏览可能让待提交记录无法恢复。

摄像头帧在浏览器处理，不由此应用上传给 Python 服务；动作模型从外部 CDN 下载。直播出去的内容由 Streamlabs / OBS 决定。

**目前不能直接公开部署。** 服务监听 `0.0.0.0`，控制接口没有身份认证；不要端口转发或开公网隧道。请使用可信网络与防火墙。凭据保存在本地文件，不是系统加密凭据库。

## 9. 常见问题

| 问题 | 怎么检查 |
|---|---|
| 登录成功但 Sub 没加 | 看分项监听、启用开关、保存的比例和最近活动；首次启用权限后重新授权 |
| 缺依赖／没有 pip | 重新运行启动脚本；必要时在项目虚拟环境执行 `python -m ensurepip --upgrade`；WSL 需对应 Python 版本的 venv 包 |
| missing client secret | 先重新授权；反复出现需要检查应用注册和 token 刷新，不要公开发送 secret |
| 8080 被占用 | 检查旧实例；确认后停掉旧实例，不要反复启动多个 |
| 浏览器黑屏 | 点击 Start Camera、检查权限和设备、释放其他摄像头使用者 |
| 浏览器正常但 Streamlabs 黑屏 | 确认是窗口捕获、选对 Chrome / Edge 窗口、未最小化，不是旧 Browser Source |
| 另一个页面占用 | 关闭多余 Camera Overlay，等待约 8 秒后重试 |
| 动作没计数 | 检查 Capture 模式和校准提示，再检查模型、站位、连接和本地保存错误 |
| Completed 不变 | Twitch 是否被检测为正在直播？未知／离线时不会增加本场次数 |
| 队列不动 | 要点 Start / resume queue，而不只是 Capture squats；检查摄像头及可选 League 检查 |
| 等待同步 | 恢复服务，保持同一浏览器来源打开；不要清除网站数据 |

League 检查默认关闭。启用后只检查**手动开始队列**，不会阻止兑换入队或打赏加数，也不是开始之后持续强制检查。Riot API、账号隐私或 Streamer Mode 等限制会影响结果，不要把它当作绝对可靠的游戏状态判断。

## 10. 还可以改进什么

建议下一轮优先做：

1. 用真实摄像头验证个人校准，继续改善不同站位、体型和光线下的识别。
2. 误计纠正、取消挑战以及清楚的欠账调整说明。
3. 自动私人备份与可验证的恢复流程。
4. 控制接口保护、凭据保护，再做 Windows 安装包。

这些是待办，不是已完成功能。自动测试不能替代真实摄像头、长时间直播和第三方事件联调。
